# MetaPulse — 飲食、斷食與用藥記錄

[![Ko-fi](https://img.shields.io/badge/Ko--fi-%E8%AB%8B%E6%88%91%E5%96%9D%E6%9D%AF%E5%92%96%E5%95%A1-FF5E5B?logo=ko-fi&logoColor=white)](https://ko-fi.com/jjptt1980)

個人用的飲食點數、斷食與用藥記錄網頁 app。純前端、不需要伺服器，資料存在你自己的裝置。

**線上使用：** https://killnopig.github.io/metapulse/

> 本 app 是個人記錄與趨勢檢視工具，不是醫療器材，不提供診斷、治療或用藥建議。點數、熱量與營養素（含 AI 辨識結果）都是粗略估算。

## 主要功能

- **飲食運動頁**：卡片依「現在最重要的事」排序。服藥時間到時服藥卡貼在畫面頂端；斷食中而且還沒達標時，斷食卡展開在最上面，點數卡縮成一行；打針當天最上面一行提醒。
- **運動**：飲食運動頁的運動卡，按「記運動」選種類（籃球、壘球、高爾夫等，常用的排前面）和分鐘數，依「MET × 體重 × 時間」估算消耗，可以手改；加回點數＝消耗 × 0.75 ÷ 40。Health Connect 的手錶消耗會自動加入，手動記錄存在 `exercise`，跟著 Drive 同步。
- **今日剩餘＋存摺**：每日點數（7 天額度 ÷ 7，已內含熱量赤字）＋ 運動加回 − 今天吃的＝今日剩餘；每天剩下的加總＝存摺（期間可選：最近 7 天滾動、每週日、每週一開始）。保底只在晚上 8 點後還吃太少時提醒。計算在 `js/ledger.js`。
- **週報**：記錄天數、達標天數（剩餘 ≥ 0）、運動賺取、體重，和上一段比較；每天的剩餘點數長條（0 為線）；點開時用 Gemini 自動產生白話總結（同一段期間只產生一次）。
- **服藥提醒**：設定藥名與時間（24 小時制），飲食頁按「已服用」記錄；服藥記錄月曆每一天都可以修改；記錄存在 `medLog`，跟著 Drive 同步。
- **淨體重趨勢**：淨體重＝體重 ×（1 − 體脂率）。最近 28 天平均和再前 28 天平均比較（各需 6 天以上有體脂），±0.5% 以內算持平、下降 0.5～1.5% 算小幅、超過 1.5% 算明顯；另外顯示減掉的重量裡脂肪佔多少。門檻在 `config.js` 的 `LONGTERM`。
- **圖表**：每天的數值是淡色小點，粗線是 7 天平均；血壓有 130/80 參考線（台灣高血壓治療指引的居家血壓目標），BMI 背景分成正常、過重、肥胖三區；體組成拆成小圖。「回診報告」整理最近 4／8／12 週的重點給醫師看，勾「給 AI」會加上說明和完整數據；也可以把所有圖表合成一張圖。
- **通知（只有 MetaPulse app）**：服藥（每天）、注射日（早上，可設定時間）、斷食（階段轉換與達標，或每小時），「晚上不打擾」時段內不發。設定頁有通知狀態與「測試通知」。
- **自訂音效**：斷食開始／結束可以換成自己的音效檔，只存在那台裝置的 IndexedDB，不上傳、不備份。內建語音 `assets/zawarudo.m4a` 是用 macOS 內建語音錄的。
- **清除資料**：「只清除飲食和斷食記錄」會連雲端一起清；「清除全部資料」只清這支手機，雲端不動。還原別的存檔時，如果手機已有記錄或已連線 Drive，只提供「只加入、不刪除」或「先清除再還原」，避免把雲端的真資料記成刪除。

## 點數怎麼算

```
點數 = 蛋白質g×4÷50 + 碳水g×4÷40 + 脂肪g×9÷35 − 纖維g÷5
```

不小於 0，四捨五入到 0.5。大約 40 kcal ≈ 1 點；蛋白質較便宜、脂肪較貴、纖維折抵。

- 每日 TDEE = BMR × 活動係數。BMR 可手動輸入，沒有就用 Mifflin-St Jeor 估算。
- 每週赤字由（目前體重 − 目標體重）÷ 預計週數推算；沒填週數時用每週減重百分比（預設 0.5%，可調）。每週減重上限為體重的 1%。
- 7 天點數池 = （TDEE × 7 − 每週赤字 kcal）÷ 40，採滾動計算（今天往前 6 天加今天）。
- 每日點數 = 7 天點數池 ÷ 7；每日保底預設 = BMR ÷ 40 點，只是提醒今天吃太少，不是要求吃到。
- 所有係數集中在 `js/config.js`。

## 從同步版搬資料

「設定」→「備份與匯入」：

- 從 Google Drive 讀取同步版的備份檔 `dose-tracker-sync.json`（需先連線同一個 Google 帳號），或貼上同步版「產生備份文字」的內容、選擇備份檔。
- 匯入前預覽新增、更新、略過的筆數與日期範圍，並列出存檔裡最新 7 天每天幾筆、會新增幾筆；從 Drive 讀取時顯示同步版的存檔時間，超過 12 小時沒更新會提醒。身高、目標體重、半衰期一併帶入。
- 可以重複匯入：以同步版每筆記錄的 id 加日期判斷（id 相同且日期相同才算同一筆），已匯入的略過，同步版改過的會更新；沒有 id 對應時用日期與數值判斷重複（血壓量測時間相差 2 分鐘內視為同一筆）。
- **只讀取同步版的資料，不會寫入、修改或刪除它。**

## Google Drive 備份

沿用同步版的 OAuth Client ID，scope 只用 `drive.appdata`。備份檔為 `metapulse.json`（包含 entries、meals、foodLibrary、fasts、profile、prefs）。每次修改後自動備份。本機與雲端會合併：各筆記錄依 id 合在一起，兩邊都有同一筆時用比較新的那份；刪除的記錄留下標記（保留 180 天），合併後不會再冒出來；寫入雲端前會先合併雲端上的版本（`js/sync.js`）。API key、主題、收合狀態等只存在本機，不列入備份。

## AI 辨識（Google Gemini）

1. 到 Google AI Studio 申請 API key。
2. 在「設定」→「AI 辨識」貼上 API key、從下拉選單選模型（預設 `gemini-3.5-flash-lite`，最快），按「測試連線」。
3. API key 只存在這台裝置，不會列入備份。照片會先縮小到 768px 再直接從手機送到 Google，app 不保存照片（可在設定開啟 200px 縮圖）。

預設使用 Interactions API（`response_format` 搭配 JSON schema 強制輸出 JSON），失敗時自動改用 `generateContent`（`responseJsonSchema`）。照片與文字共用同一個 schema（`js/gemini.js` 的 `FOOD_SCHEMA`）。

## 資料

- 本機儲存鍵：`metapulse-v1`（記錄，會備份）、`metapulse-local`（API key、主題、收合狀態等，只存在這台裝置）。同網域的其他 app（例如 `dosetrack-v1-sync`）的資料不會被讀寫。
- `entries` 沿用同步版的欄位（`date`、`dose`、`wt`、`sys`、`dia`、`pul`、`fat`、`mus`、`vis`、`bage`、`bmr`、`site`、`note`），另外加上 `time`（量測時間）與 `src`（來源）。
- `meals` 每一筆是一道食物，同一餐以 `group` 串起來；營養素以「一份」為基準存在 `per`，並存下當時算好的合計與點數。

## 斷食與長期指數

- 斷食時間＝距離最後一筆餐點的時間；也可以手動「從現在開始斷食」，記餐時自動結束。
- 階段（距上一餐）：0–4 小時消化中、4–12 開始使用肝醣、12–16 逐漸偏向脂肪、16–20 長時間斷食、20 以上蛋白質分解可能增加。上一餐超過 800 大卡或碳水 100 g 時整體往後挪 1 小時，超過 1200 大卡或 150 g 挪 2 小時。
- 三種模式：自由斷食、依施打週期（第 1～3 天建議 18:6、第 4～7 天 16:8；減重太快或長期指數有提示時一律 16:8；只建議不自動切換）、自選固定（16:8、18:6、20:4、24H 一天一餐，含進食窗口）。
- 每小時提示文字在 `js/messages.js`，可自行增刪。
- 長期攝取指數＝每天（熱量 ÷ 基礎代謝）的指數移動平均（α＝0.05），跳過沒記錄和記錄不完整（低於基礎代謝 30%）的日子；至少 21 個有效日且最近 28 天有 70% 以上才提示。
- 所有規則與門檻集中在 `js/config.js` 的 `FASTING`、`LONGTERM`。

## 開發

```bash
npm test
```

不使用打包工具：`index.html` 載入 `js/` 底下的 ES module。每個模組都透過 import map 加上 `?v=版本號`，更新後不會讀到舊快取；新增模組時記得把檔名加進 `index.html` 的模組清單。

發布新版：修改 `index.html` 裡的 `APP_VERSION`，推上 `main`。使用者開啟 app 或從背景切回時會看到「有新版本」提示。

## Omron、AI 分析與備份提醒

- **Omron CSV**（設定 →「Omron 檔案匯入」）：可一次選多個 OMRON connect 匯出的 CSV，自動辨識欄位（逗號或 Tab、中英文標題、磅換公斤），先預覽再匯入。重複判斷和 Health Connect 共用 `planMeasurements`；同一天同體重的記錄只補上缺少的體組成欄位。「復原上次匯入」和 Health Connect 共用 `metapulse-v1-undo`。
- **給 AI 分析**（圖表頁）：所有圖表合成一張淺色底高解析度 PNG（APK 用原生分享，瀏覽器用系統分享或下載），以及「複製數據摘要」純文字（`js/summary.js`）。摘要包含注射、體重、血壓、體組成、每週摘要、最近 14 天逐日，另外加上每日點數、熱量、蛋白質、斷食時數（每天最長的兩餐間隔，按過「結束進餐／結束斷食」就用那個時間）與運動消耗。
- **從其他 App 或 Excel 匯入**（備份與匯入 → 其他）：複製提示詞給 AI，請它轉成同步版格式的 JSON，貼回來會走「匯入預覽」，只加入新的身體記錄，不會取代現有資料。
- **備份提醒**：設定的天數內有新記錄、卻沒存到 Google Drive 或產生存檔文字時，在今日頁最上面提醒（預設 7 天，可設 3／7／14／30 天或不提醒，可按「今天不再提醒」）。
